# Identity Provider Comparison

Compare identity providers: features, pricing, licensing and OpenID Connect support.

An open dataset comparing 70 identity providers (Auth0, Okta, Keycloak, Clerk, Cognito, Entra ID, Ory,
Zitadel…): IAM / CIAM features, pricing, licensing, self-hosting and OpenID Connect support.

The data is open and maintained by [CerberAuth](https://www.cerberauth.com). It powers the benchmarks
published on [Nacho](https://nacho.cerberauth.com/).

## Layout

- `providers/<id>.json` — one file per provider. Shared metadata (name, abstract,
  website, license, nationality, icon, pricing) plus:
  - `type` — optional, `platform` (default; standalone hosted or self-hosted
    service/server) or `library` (embedded in the host application). Libraries
    may also list the `languages` they can be embedded in.
  - `status` — optional, `active` (default), `deprecated`, `end_of_life` or `acquired`.
  - `deploymentModels` — optional, any of `saas`, `self_hosted`, `hybrid`, `embedded`.
  - `targetAudience` — optional, any of `b2c`, `b2b`, `workforce`, `ciam`, `developer`.
  - `license` — an SPDX identifier (`Apache-2.0`, `MIT`, `AGPL-3.0-only`) or `Proprietary`
    for closed-source and commercial licenses. `licenseUrl` optionally links to the license text.
  - `pricing.currency` — ISO 4217 code of the prices. Plans may carry a machine-readable
    `amount` and `period` (`month`, `year`, `one_time`) next to the display `price`. These are only
    set for flat fees; per-unit, usage-based, ranged and custom prices stay in `price`.
  - `vendor`, `foundedYear`, `headquarters`, `acquiredBy` — optional company facts. `vendor` is who
    develops and sells the product today, `foundedYear` is when the original company or project started,
    `headquarters` is a country code plus optional city and is left out when sources disagree.
  - `openSource` — `{ isOpenSource, model }` where `model` is `fully_open`, `open_core` or `source_available`.
  - `repositories` — source repositories (`core`, `sdk`, `infrastructure`, `docs`). Stars, contributors and
    latest release are generated by `npm run stats` (set `GITHUB_TOKEN` to avoid rate limits), which stamps
    each repository with `statsUpdatedAt`.
  - `hosting` — `regions` (data residency, ISO country codes or `EU`, `APAC`, `SAM`, `MEA`) and
    `selfHostRequirements` (`runtime`, `database`, `container`).
  - `sla` — `{ uptimePercent, url, scope }` for published uptime commitments.
  - `pricing.freeTierMau`, `hasEnterprisePlan`, `contactSalesRequired`, and per plan:
    - `deployment` (`saas`, `self_hosted`, `hybrid`, `embedded`) — products that can be self-hosted or bought
      managed get one plan per deployment (e.g. Ory "Open Source" vs "Production").
    - `amount` / `period` — flat base fee. `usage` — `{ metric, included, min, max, rates[] }` graduated rates per
      MAU, DAU, user, ... A `usage` without `rates` means overage prices are not published (cost shown as a lower bound).
    - `limits` — hard caps (`connections`, `organizations`, ...) that rule a plan out.
  - `features[].plans` — required on every feature: the plans that include it (all of them when it is on every plan, none when unsupported or add-on only). The plans live on the
    feature, there is no per-plan feature list.
  - `features[].addOn` — paid add-on: `{ name, price, amount, period, unit, per, included, rates[], plans }`. On a plan
    that lacks the feature it unlocks it; on a plan that has it, it is the fee for units above `included`. Features
    with the same `name` are one purchase. Volume pricing (e.g. cheaper connections past the 15th) goes in `rates`,
    the same graduated `{ upTo, amount, per }` shape as `usage.rates`; a last rate with `upTo` means prices above it are
    custom.
  - `features[]` and `oidc.features[]` may also carry `tier` (`basic`, `standard`, `advanced`, `enterprise`),
    `sinceVersion` and `betaStatus` (`ga`, `beta`, `preview`, `experimental`).
  - `aliases`, `tags` — optional former or alternate names, and free-form lowercase search keywords.
    Tags do not repeat capabilities that are already tracked as features.
  - `documentationUrl`, `changelogUrl`, `statusPageUrl`, `communityUrl` — optional links, only set when the page exists.
  - `governance` — optional, `vendor_led`, `foundation` or `community`.
  - `supportChannels` — optional, any of `email`, `chat`, `phone`, `community`, `slack`.
  - `userLimits` — optional `{ maxUsers, maxTenants }` hard limits, left out when there are none.
  - `migrationTools` — optional list of `{ from, url }` guides for importing users from another provider.
  - `pricing.pricingLastVerified` and `pricing.trialDays` — optional date the prices were last checked, and the
    length of the free trial of paid plans. `pricingLastVerified` is only set when the pricing page was actually
    rechecked, `lastVerified` covers the rest of the file.
  - `oidc.discoveryUrl` — optional fixed public discovery document URL, left out when it depends on a tenant or domain.
  - `oidc.certified` — optional `{ profile, version, certificationUrl }` OpenID Foundation OP certification.
  - `oidc.features[].values` lists supported options, like `features[].values`.
  - `sdks` — optional list of `{ language, framework, url, official }` SDKs.
  - `lastVerified` — optional date (`YYYY-MM-DD`) the file was last checked.
  - `nationality` — country of the vendor. Left out for community projects without a company behind them
    (Authelia, Better Auth).
  - `features` — the IAM / CIAM feature list. Every provider lists the 110 catalog features. Auth0 also carries `rules_deprecated` and `hooks_deprecated`, which are not in the catalog.
  - `oidc.features` — the OpenID Connect feature list, kept in its own category.
- `definitions/`
  - `iam-categories.json`, `oidc-categories.json` — ordered category definitions
    (`identifier` + `translationKey`).
  - `iam-features.json`, `oidc-features.json` — the feature catalogs (identifier,
    category, tier, status, canonical English name/description, spec links).
  - `statuses.json` — allowed feature support statuses.
  - `tiers.json` — allowed feature tiers.
- `i18n/<locale>.json` — translations for category and feature names /
  descriptions, split into `iam` and `oidc`. English is the canonical fallback
  and mirrors the catalogs; other locales only carry overrides.

## Contributing

Found a missing provider, a wrong price or an outdated feature? Please fork the repository and open a
pull request, or [open an issue](https://github.com/cerberauth/identity-provider-data/issues). Run
`npm test` before submitting to make sure the data is valid.

## About CerberAuth

[CerberAuth](https://www.cerberauth.com) builds open source tools around API and authentication
security, including:

- [VulnAPI](https://vulnapi.cerberauth.com) — open source API vulnerability scanner.
- [Nacho](https://nacho.cerberauth.com/) — OAuth 2.0 and OpenID Connect client creation helper, with
  identity provider benchmarks built on this data.
- [AUMS](https://www.cerberauth.com/aums/) — admin dashboard to manage users, organizations and audit
  logs on top of your existing CIAM provider.
- [Taco](https://www.cerberauth.com/taco/) — one dashboard for all your OAuth 2.0, OpenID Connect and
  SAML clients.
