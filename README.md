# identity-provider-data

Structured data about identity providers: IAM / CIAM capabilities and OpenID
Connect protocol support.

## Layout

- `providers/<id>.json` — one file per provider. Shared metadata (name, abstract,
  website, license, nationality, icon, pricing) plus:
  - `type` — optional, `platform` (default; standalone hosted or self-hosted
    service/server) or `library` (embedded in the host application). Libraries
    may also list the `languages` they can be embedded in.
  - `status` — optional, `active` (default), `deprecated`, `end_of_life` or `acquired`.
  - `deploymentModels` — optional, any of `saas`, `self_hosted`, `hybrid`, `embedded`.
  - `targetAudience` — optional, any of `b2c`, `b2b`, `workforce`, `ciam`, `developer`.
  - `license` — an SPDX identifier (`Apache-2.0`, `MIT`, `AGPL-3.0-only`) or `Proprietary`
    for closed-source and commercial licenses. `licenseUrl` optionally links to the license text.
  - `pricing.currency` — ISO 4217 code of the prices. Plans may carry a machine-readable
    `amount` and `period` (`month`, `year`, `one_time`) next to the display `price`. These are only
    set for flat fees; per-unit, usage-based, ranged and custom prices stay in `price`.
  - `vendor`, `foundedYear`, `headquarters`, `acquiredBy` — optional company facts. `vendor` is who
    develops and sells the product today, `foundedYear` is when the original company or project started,
    `headquarters` is a country code plus optional city and is left out when sources disagree.
  - `openSource` — `{ isOpenSource, model }` where `model` is `fully_open`, `open_core` or `source_available`.
  - `repositories` — source repositories (`core`, `sdk`, `infrastructure`, `docs`). Stars, contributors and
    latest release are generated by `npm run stats` (set `GITHUB_TOKEN` to avoid rate limits), which stamps
    each repository with `statsUpdatedAt`.
  - `hosting` — `regions` (data residency, ISO country codes or `EU`, `APAC`, `SAM`, `MEA`) and
    `selfHostRequirements` (`runtime`, `database`, `container`).
  - `sla` — `{ uptimePercent, url, scope }` for published uptime commitments.
  - `pricing.freeTierMau`, `hasEnterprisePlan`, `contactSalesRequired`, and per plan `mauIncluded` and
    `featuresIncluded` (the gated features whose `plans` name that plan; the validator keeps both in sync).
  - `features[]` and `oidc.features[]` may also carry `tier` (`basic`, `standard`, `advanced`, `enterprise`),
    `sinceVersion` and `betaStatus` (`ga`, `beta`, `preview`, `experimental`).
  - `sdks` — optional list of `{ language, framework, url, official }` SDKs.
  - `lastVerified` — optional date (`YYYY-MM-DD`) the file was last checked.
  - `features` — the IAM / CIAM feature list.
  - `oidc.features` — the OpenID Connect feature list, kept in its own category.
- `definitions/`
  - `iam-categories.json`, `oidc-categories.json` — ordered category definitions
    (`identifier` + `translationKey`).
  - `iam-features.json`, `oidc-features.json` — the feature catalogs (identifier,
    category, tier, status, canonical English name/description, spec links).
  - `statuses.json` — allowed feature support statuses.
  - `tiers.json` — allowed feature tiers.
- `i18n/<locale>.json` — translations for category and feature names /
  descriptions, split into `iam` and `oidc`. English is the canonical fallback
  and mirrors the catalogs; other locales only carry overrides.
